## What changed today

### Training (clapha-il, all deployed)
- `--next-play` heads: on every decision, how many decisions until this player's next play (bins 0,1,2,3-4,5-8,9-16,17+)
  and which hand card. Aux only; the policy never reads it. Pilot queued (93747).
- `timing_gain` replaces play_recall / play_precision, which were 0 for every model (P(play) ~4% never reaches 0.5).
- Pilots cut to base / no-attention / no-unit-states / next-play (large, effect-ids, chunk512 dropped by Jason).
- Speed: validation read every game to find the 2% held out (half of a 7 h pilot): offsets found once now (identical
  chunks). Batches cut the object axis to the most objects present (~12 average of 128 slots; same loss, gradients to
  rounding). Own-hand reconstruction incremental (+10%, byte-identical features). Opt-in `--bf16`, `--cosine` for the full
  run. Checkpoints carry their vocabulary. `bench_train.py` (job 93775) measures features per core vs GPU rates (fp32 128
  slots / cut / bf16 / compile): the loader's 15 workers give ~13.5k decisions/s, the GPU took ~12k in fp32, so a faster GPU
  makes the loader the limit; the planned answer is a compact feature cache (~1 KB a decision; 864 TB free) if the bench
  confirms.
- `feature_hashes.py`: do two checkouts build the same inputs and labels.

### PPO port (this repo, on `ppo-port`, not deployed)
- `il/policy.py` replaces `il/clapha_agent.py`: load (vocab from the checkpoint), `Inputs` (PlayerView per player on
  ClaphaEngine.record()), packed rows (present objects, int32 ids, legal tiles as bits: ~4 kB a decision), the policy
  (what / which card / tile, each sampled; only waiting while our play is in flight; ability floor 1%), `Agent`.
- `il/actors.py` collectors and decision servers on it (no CUDA graphs); `il/rl.py` update evaluates what / card on every
  decision and the tile where a card was played; KL to IL exact for what / card, k3 estimate for the tile; dropped the
  aux tower head and the opponent-deck value input. `il/arena.py` plays the same policy and now presses abilities (they
  were dropped for every model); default delay 23-27 ticks.
- `ClaphaEngine.record()` reads objects once. `tools/train.sbatch` / `satellite.sbatch` take INIT / RUN; `tools/check.sbatch`
  (inputs parity, decision time, 16 arena games, 5 PPO updates; REF= checks a branch); `tools/time_decision.py`.
- Tested on the Mac only (`il/test_policy.py`): packed inputs give the same outputs; sample() and the update's log-probs
  agree; an update starts at KL 0. The engine test is cr-check 93752. Jason approved deploying once it passes.
- Measured (before the login-node rule): ~1.4 CPU-s a game (engine 0.4, record 0.3, both players' inputs 0.7) vs ~1.0 for
  the old model. Sharing per-object work between the players gained 3%: reverted.

- The PPO port has not run in the engine yet. Its choices: no temperature (T=1 on every head), the in-flight mask, the
  1% ability floor, k3 for the tile KL, no aux head, no CUDA graphs (GPU throughput of the 4.7 M model unknown).

  listed above.
